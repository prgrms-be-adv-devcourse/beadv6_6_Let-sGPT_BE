# 재고 캐시 복구

기동·예약 시 원장으로 재고와 구매자 집계를 재구성하는 기존 흐름을 유지한다.
삭제가 Redis fence에서 거절된 경우에는 복구를 등록하지 않는다.
제거가 허용됐거나 응답이 불명확한 경우에만 해당 트랜잭션 롤백 뒤 복구한다.

## 동시 변경과의 경계

- 차감·취소는 Redis 변경 전에 시도별 UUID 토큰을 등록하고, 원장 확정까지 유지한다.
  캐시 없이 원장만 기록하는 취소도 같은 경계를 사용한다.
- 복구는 진행 토큰이 없을 때 lease를 획득한 뒤 새 DB 스냅샷을 연다.
  드롭 행 잠금은 집계부터 Redis 게시까지 유지한다.
- 게시와 해제는 같은 소유자 UUID만 허용한다. 만료된 복구가 늦게 도착해도
  이후 변경이나 새 소유자의 lease를 덮지 않는다.
- 정상 변경끼리는 직렬화하지 않는다. 다만 진입·완료에 Redis 왕복이 추가된다.

복구 중 변경은 `DROP_STOCK_CHANGE_IN_PROGRESS`(503)로 거절한다.
등록·삭제 보상을 포함한 런타임 워밍의 일시적인 진입 거절은 1초 뒤 재시도하되
종료 시각·취소된 예약은 넘지 않는다.
기동 복구의 거절은 그대로 기동 실패로 전달한다.

## 실패와 적용 조건

복구 lease는 `drop.recovery.lease`(기본 30초)로 제한하지만 진행 토큰에는 TTL을 두지 않는다.
저장·보상 결과가 불명확하면 토큰을 남겨 재구축을 차단한다.
원장 완료 뒤 토큰 정리가 실패해도 이미 완료한 재고를 역보상하지 않는다.

남은 토큰을 시간만 보고 지우지 않는다. 해당 요청의 원장·캐시 효과와 살아 있는 작업을
확인한 뒤 복구해야 한다. 자동 강제 해소나 Redis 전체 유실 복원은 제공하지 않는다.
원장 재구축도 기존 주문 멱등키를 자동 초기화하지 않는다.

최초 적용은 구버전 상품 프로세스와 진행 요청·DB 트랜잭션이 종료된 뒤 수행한다.
새 진입 규칙을 모르는 구버전과 혼합 실행하지 않는다.
신버전의 기동 복구 후 재고·구매자 집계를 확인한다.
단일 replica 설정만으로 이전 프로세스 종료를 보장한다고 가정하지 않는다.
