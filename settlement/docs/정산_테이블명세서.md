# 정산 도메인 테이블 명세

> 2026-07-27 `dev`의 JPA 매핑 기준. 정산 서비스는 PostgreSQL `settlement` 스키마와
> `ddl-auto=update`를 사용한다. 아래 타입은 JPA가 의도하는 PostgreSQL 타입이며 실제 환경의
> 최종 DDL은 DB에서 다시 확인한다.

## 공통 기준

- 서비스 포트: `9140`
- 식별자: PostgreSQL native `UUID`, Hibernate time-based UUID generator
- 금액: `BIGINT`, 원화 정수
- 정산월: `VARCHAR(6)`, `yyyyMM`
- 타 도메인 ID와 정산 테이블 사이에는 물리 FK가 없다. 모두 값 참조다.
- Spring Batch 메타데이터는 `settlement.batch_*` prefix를 사용한다.

## 테이블 목록

| 테이블 | 역할 |
|---|---|
| `settlement_batchs` | 월 정산·재처리 배치 실행 이력 |
| `settlement_orders` | 결제 완료 건의 정산 원장 |
| `settlement_refunds` | 환불 완료 건의 정산 차감 원장 |
| `settlement_adjustments` | 정산 완료 후 발생한 보정 |
| `seller_settlements` | 판매자별 월 정산 결과 |
| `daily_reconciliation_results` | 일별 payment↔settlement 대사 결과 |
| `daily_reconciliation_discrepancies` | 일별 대사 불일치 상세 |

> `settlement_batchs`는 오탈자처럼 보이지만 현재 `@Table`에 선언된 실제 이름이다.
> 문서에서 임의로 `settlement_batches` 또는 `settlement_batch`로 바꾸지 않는다.

## `settlement_batchs`

| 컬럼 | 타입 | 제약·의미 |
|---|---|---|
| `batch_id` | UUID | PK |
| `settlement_month` | VARCHAR(6) | NOT NULL |
| `batch_type` | VARCHAR(30) | `LOAD_PAYMENT`, `LOAD_REFUND`, `SETTLEMENT_RUN`, `SETTLEMENT_RETRY` |
| `status` | VARCHAR(20) | `READY`, `RUNNING`, `COMPLETED`, `FAILED` |
| `started_at` | TIMESTAMP | 실행 시작 시각 |
| `ended_at` | TIMESTAMP | 완료·실패 시각 |
| `total_order_count` | INTEGER | NOT NULL, 기본 0 |
| `total_seller_count` | INTEGER | NOT NULL, 기본 0 |
| `total_settlement_amount` | BIGINT | NOT NULL, 기본 0 |
| `fail_reason` | VARCHAR(500) | 배치 실패 사유 |
| `created_at` | TIMESTAMP | NOT NULL |

| 컬럼 | 타입 | 제약·의미 |

| `buyer_id` | UUID | NOT NULL, member 값 참조 |

| `order_amount` | BIGINT | NOT NULL |
| `paid_amount` | BIGINT | NOT NULL |
| `fee_amount` | BIGINT | NOT NULL |
| `refund_amount` | BIGINT | NOT NULL, 정산 전 환불 누계 |

| 컬럼 | 타입 | 제약·의미 |
|---|---|---|

| `refund_id` | UUID | NOT NULL, UNIQUE, payment 환불 ID 값 참조 |

|---|---|---|

## `seller_settlements`

| 컬럼 | 타입 | 제약·의미 |
|---|---|---|
| `seller_settlement_id` | UUID | PK |
| `batch_id` | UUID | NOT NULL, `settlement_batchs.batch_id` 값 참조 |
| `settlement_month` | VARCHAR(6) | NOT NULL |
| `seller_id` | UUID | NOT NULL |
| `total_order_count` | INTEGER | NOT NULL |
| `total_paid_amount` | BIGINT | NOT NULL |
| `total_fee_amount` | BIGINT | NOT NULL |
| `total_refund_amount` | BIGINT | NOT NULL |
| `total_adjustment_amount` | BIGINT | NOT NULL |
| `final_settlement_amount` | BIGINT | NOT NULL, `paid - fee - refund + adjustment` |
| `status` | VARCHAR(20) | `READY`, `COMPLETED`, `FAILED` |
| `completed_at` | TIMESTAMP | 완료 시각 |
| `fail_reason` | VARCHAR(500) | 판매자 단위 실패 사유 |
| `failed_at` | TIMESTAMP | 판매자 단위 실패 시각 |

`(seller_id, settlement_month)`가 UNIQUE라 같은 월의 실패 건 재처리는 새 행을 만들지 않고 기존
행을 다시 계산한다. `batch_id`와 `(seller_id, settlement_month)` 인덱스가 있다.

## `daily_reconciliation_results`

| 컬럼 | 타입 | 제약·의미 |
|---|---|---|
| `id` | UUID | PK |
| `business_date` | DATE | NOT NULL, UNIQUE |
| `status` | VARCHAR(20) | `SUCCESS`, `DISCREPANCY_FOUND`, `CALL_FAILED` |
| `payment_count` | INTEGER | NOT NULL |
| `total_payment_amount` | BIGINT | NOT NULL |
| `refund_count` | INTEGER | NOT NULL |
| `total_refund_amount` | BIGINT | NOT NULL |
| `expected_settlement_amount` | BIGINT | NOT NULL |

같은 영업일을 다시 대사하면 새 행을 추가하지 않고 기존 결과를 최신 값으로 덮어쓴다.

## 이벤트 반영 관계

```text
payment.settlement.events
  ├─ PaymentSettlementCompleted → settlement_orders
  └─ RefundSettlementCompleted
       ├─ 정산 전  → settlement_refunds + settlement_orders.refund_amount
       └─ 정산 후  → settlement_refunds + settlement_adjustments

월 정산
  └─ settlement_orders + settlement_adjustments
       → seller_settlements
       → settlement_orders.seller_settlement_id
```
